# easySTL

使用 C++20，自己实现动态数组容器 easystl::vector，再实现独立内存池 easypool，通过编码与 review 学习对象生命周期、资源管理与泛型编程。

实现前可以选做空间与对象的短实验，前期使用 std::allocator<T>、std::construct_at 和 std::destroy_at。七个阶段依次完成基本存储与追加、容器复制、位置与数量修改、遍历与范围、移动与原地构造、独立内存池，以及池分配器接入与整体检查。不要求先自制普通分配器或整套迭代器和算法工具。

## 入口

- [PLAN.md](PLAN.md)：从自行实现 easystl::vector 的目标出发，先说明各模块要解决的问题和工具职责，再介绍具体名称、测试任务与接口；同时说明本项目的阶段安排及原因。
- [record.md](record.md)：学习者自行维护的进度、验证结果、学习疑问及下一步。
- [AGENTS.md](AGENTS.md)：与 AI 协作时的任务范围、review 方式和操作边界。

第一次阅读先看 PLAN.md 开头的 STL 组成简介，了解每类组件在哪些操作中起作用、调用者通常直接使用什么、库在内部完成什么，以及本项目选择实现哪些部分。再看 std::vector 的使用例子与阶段安排，把各阶段对应到组件或支撑工作，分清“已经分配存储空间”和“已经在其中构造对象”。继续学习时先看 record.md，核对已有实现和当前疑问，再回到对应阶段的测试与实现逻辑。

阅读状态变化时，先看具体调用：reserve 预留空间，push_back 在需要时构造新元素，pop_back 销毁末元素，容器析构时再完成剩余清理。PLAN 会列明调用前的条件和调用后的结果，并区分标准库示例与本项目计划采用的实现策略。

可以自行编码，也可以让 AI 分步实现；每次完成一小部分并检查结果，将实际进度与疑问记录到 record.md。PLAN.md 作为学习教程，通常不需要随个人进度修改。最终交付计划包含这些文档和独立的参考答案目录（暂名 reference/，待整理）；练习目录、测试与库代码由读者按步骤自行创建。

## 使用方式

先阅读 PLAN.md 中的整体说明，再选择当前阶段的测试任务，按需创建目录、编写测试和实现。开头的标准库短实验可以选做，用来观察预留空间与对象构造的区别。

计划采用 easystl/、easypool/ 两个独立模块，测试与短实验统一放在 test/。当前学习安排是在 test/ 中建立共用 Makefile，根目录统一构建入口留待后续阶段建立；目录和文件随实践逐步创建。具体学习进度和本地验证记录见 record.md。

旧版源码、测试与教程保存在 Git 提交 `f18416a` 中。可用 `git show f18416a:known-issues.md` 查阅旧问题，实施对应功能时设置回归。
